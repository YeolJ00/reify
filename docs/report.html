Nothing in this scene is currently measurable from generated video

We stage physics experiments, film them with a video model, and recover material parameters by measuring the motion. This report covers the point at which the instrument was turned on itself: the estimator was reporting confident numbers for clips in which nothing moved.

01The estimator was manufacturing numbers

The retired fitter searched a parameter grid for the value whose hand-weighted motion signature best matched the track. A grid always returns a best match; it never asks whether the observation constrains anything. Measuring the physics directly asks that first.

02Why it went unnoticed: path length integrates noise

The old "did it move" guard measured path length — the sum of per-frame steps. That accumulates tracking jitter without bound: 49 frames of ±2 px noise manufactures roughly 100 px of apparent travel from a stationary object. Net displacement does not accumulate, because noise cancels.

Over 55 collision clips, the ceramic vase's subject never displaced more than 21 px and the rubber duck never more than 17 px

— against the 23–43 px they had to cover to reach their partner. The videos did not contain the experiment, and the fits were reading sub-10-pixel jitter.

03The rebuilt estimator: measure, don't search

Each probe is analytically invertible, so nothing is searched:

  • drop → restitution e = |v_up| / |v_down| — dimensionless
  • slide → friction μ = |a| / g — the only one needing the px↔m scale
  • collide → m_target/m_mover = (v_pre − v_post) / v_target — scale and frame rate cancel exactly

Every quantity is a velocity from a least-squares fit over about five frames, which yields a standard error for free. Uncertainty is propagated rather than guessed, so each parameter arrives as a value with an interval — and an interval spanning the plausible range is the “not identifiable” verdict. Every tunable is gone: no grids, no feature weights, no scoring variants, no agreement threshold. The “did it move” test became a significance test on the fitted velocity.

A probe-design error this exposed.

The μ ≈ 0.01–0.09 readings are about right for the rolling resistance of a ball on wood — which is not the Coulomb μ the simulator consumes. A sphere's deceleration cannot measure sliding friction. The slide probe is valid only for objects that actually slide, so the baseball and apple need a different experiment or a rolling model.

05Corrections to earlier reporting

  • 60 fps was not the diagnosis for mass. The per-take fits were individually decisive and mutually contradictory, which is generator non-repeatability, not temporal resolution. Frame rate cannot be the binding constraint while half the clips contain no motion.
  • There is no ground truth in this pipeline. Errors were previously quoted against “true” densities that came from a hardcoded table of textbook guesses, anchored by a reference value taken from that same table. Downloaded meshes have no true density.
  • Three “established” friction values did not survive. Direct measurement does not reproduce any of them.

06What this says about the next step

The binding constraint is data collection, not estimation. Before designing further probes, the generator needs screening: produce a few clips per candidate experiment and measure whether the intended object moved at all. Static-equilibrium probes — flotation for absolute density against water, a balance beam for mass ratio — would remove both the frame-rate sensitivity and the arbitrary density anchor, but they still assume the model animates the object, which for the vase and duck it does not.
