Per-instance inverse simulation · measurement report

Three times, the instrument turned out to be the thing being measured

We stage physics experiments, film them with a video model, and recover material parameters from the motion. Every layer of that pipeline — the estimator, its acceptance gate, and the point tracker underneath both — has now been caught reporting its own failure as a property of the video. This report is what survived.

01The estimator was manufacturing numbers

The retired fitter searched a parameter grid for the value whose hand-weighted motion signature best matched the track. A grid always returns a best match; it never asks whether the observation constrains anything. Measuring the physics directly asks that first. This comparison runs both estimators over identical tracks, so it is unaffected by everything that follows.

02The rebuilt estimator: measure, don't search

Each probe is analytically invertible, so nothing is searched:

  • drop → restitution e = |v_up| / |v_down| — dimensionless
  • slide → friction μ = |a| / g — the only one needing the px↔m scale
  • collide → m_target/m_mover = (v_pre − v_post) / v_target — scale and frame rate cancel exactly

Every quantity is a velocity from a least-squares fit over about five frames, which yields a standard error for free. Uncertainty is propagated rather than guessed, so each parameter arrives as a value with an interval — and an interval spanning the plausible range is the “not identifiable” verdict. Every tunable is gone: no grids, no feature weights, no scoring variants, no agreement threshold.

03The audit that corrected itself

An earlier version of this report stated that 68 of 93 takes contained no measurable motion. That was wrong. It was computed from tracked centroids, and the tracker fails on these clips in a way its own diagnostics cannot see: points stay “visible” while sitting on the background, so a duck that visibly fell to the table measured 6 px of motion. 38% of the takes behind that claim had a suspect tracker.

04The finding the old audit could not see

The appearance channel adds a state that centroid tracking had no way to express: the object stops being the object. All 14 such takes are the brass pot, which transforms mid-clip from a lidded pot into a wide shallow bowl.

No θ explains this.

A parameter that merely has to produce a plausible physical motion is a generous bar, and asset degradation fails it outright: there is no density, friction or restitution that turns a pot into a bowl. This is not identifiability and not frame rate. It is asset integrity, and it is a different problem from the one we were solving.

05Corrections

  • “The videos do not contain the experiment” was an instrument artefact. Stated twice, on tracker evidence. 71 of 93 takes move.
  • 60 fps was not the diagnosis for mass, and is no longer proposed as a requirement. The per-take fits were individually decisive and mutually contradictory, which is generator non-repeatability, not temporal resolution.
  • There is no ground truth in this pipeline. Errors were once quoted against “true” densities from a hardcoded table of textbook guesses, anchored by a value from that same table.
  • A max-excursion statistic is not a displacement. The first appearance-based audit used peak displacement and scored 38 px of “motion” for a vase that never left its spot, because it transiently splits into two blobs and re-forms. Switching to end-to-end displacement moved six takes from moving to static — the same mistake as the original path-length gate, made a second time.

06Known limits of the current instrument

  • One clip (rubber_duck_collide_seed0) is classed as moving at 0.55 object-widths where visual inspection says the duck re-forms rather than translates. The appearance tracker cannot fully separate “translated” from “re-rendered nearby”.
  • The audit is calibrated against roughly a dozen clips inspected frame by frame, not against all 93.
  • Parameter values still depend on point tracks that have not been re-validated.
